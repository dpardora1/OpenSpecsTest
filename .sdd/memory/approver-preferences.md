# Preferencias del aprobador (`@dpardora1`)

Cómo le gusta al humano recibir el trabajo para aprobarlo rápido. Todos los agentes que escriben para él (Issues, specs, PRs, resúmenes) las respetan. Las mantiene `retrospective` a partir de sus comentarios (Issues `lesson-candidate`), siempre con la cita original.

| ID | Preferencia | Evidencia |
|---|---|---|
| P-001 | **PRs lo más pequeñas y simples posible**: un propósito por PR; la spec en una PR separada de solo Markdown | "Las PR deberían ser lo más sencillas posibles ya que en principio las aprobaré yo" (sesión de arranque, 2026-10-15) |
| P-002 | **Todas las evidencias de validación en la propia PR**, para aprobar sin investigar | "Necesito todas las herramientas posibles de validación para que me faciliten la aprobación" (2026-10-15) |
| P-003 | El humano **no escribe nada**: solo aprueba, rechaza o comenta. Cualquier acción manual que necesite debe pedirse con instrucciones exactas y mínimas | "Como es una demo, la idea es que yo no escriba nada" (2026-10-15) |
| P-004 | Español en Issues, specs, PRs y resúmenes; respuestas concisas y directas | Conversación de arranque; "solo contesta" (2026-10-15) |
| P-005 | Quiere ver **métricas de proceso** (tiempos, tokens, trazas) y que la IA **aprenda** entre iteraciones | Petición de memoria y observabilidad (2026-10-15) |
| P-006 | Antes de cada acción manual suya, una lista corta numerada de "lo que te toca" con enlaces directos | Patrón de las PRs #1–#3 aceptado sin cambios |
